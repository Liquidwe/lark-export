# Lark 文档迁移工具

Lark 官方没有提供跨组织迁移文档的能力。这个工具把文档读取到服务器上的数据库，再写到新组织，并保持原有层级。

## 两种身份

| | 团队成员 | 管理员 |
|---|---|---|
| 登录方式 | Lark 账号授权 | `ADMIN_PASSWORD` 密码 |
| 能读取什么 | 只有本人的“我的文档库”和云空间“我的空间”，不能输入链接 | 任意知识库链接（机器人能访问的范围） |
| 写到哪里 | 本人在新组织的文档库顶层和云空间，需要再授权一次新组织账号 | 任意知识库链接 |
| 用谁的权限 | 成员本人 | 机器人 |
| 能看到谁的记录 | 只有自己的 | 自己的全部内容；成员只能看姓名、状态和数量，看不到标题、正文和报错内容 |

成员的流程是三步：读取文档库和云空间、授权新组织、写入。写入不会覆盖新组织已有的内容，但重复写入会产生重复文档。

云空间的内容会放在新账号云空间里一个名为“我的空间”的文件夹中，里面的文件夹层级保持不变。只读取本人“我的空间”里的内容，“与我共享”的文件不会读取。

## 管理员按链接迁移

迁移分两步，中间的数据都在服务器上：

1. **读取**：输入源链接，遍历整棵目录，把文档、电子表格、多维表格、画板和附件存到本地。页面会显示节点总数和每种类型的数量。
2. **写回**：输入目标链接，目标节点会变成源目录的第一层：它改用源文档的标题和正文，子文档直接写到它下面。工具先建好目录结构，再填内容，最后把文档之间的链接指向新位置。

例如把 `Kili-AI`（下面有 1、2、3 三篇子文档）迁移到 `33`，结果是 `33` 改名为 `Kili-AI`，1、2、3 直接在它下面。

迁移不会修改或删除源文档，但**会覆盖目标文档的标题和正文**，目标下已有的子节点会保留。开始前页面会提示具体会覆盖什么。被覆盖的正文只能尝试从 Lark 文档的历史记录中找回，工具本身不做备份。如果源文档或目标不是普通文档（比如多维表格），无法合并，会作为子节点写到目标下面。目标不能是源目录中的文档。

## 快速开始

### 1. 配置

```bash
cp .env.example .env
```

然后编辑 `.env`：

| 变量 | 必填 | 说明 |
|---|---|---|
| `LARK_APP_ID` / `LARK_APP_SECRET` | 是 | 当前组织的机器人 |
| `LARK_TARGET_APP_ID` / `LARK_TARGET_APP_SECRET` | 成员迁移或跨组织时必填 | 新组织的机器人。管理员按链接迁移时留空则使用上面那组 |
| `ADMIN_PASSWORD` | 管理员需要 | 管理员密码，建议至少 12 位。不设置就无法用管理员身份登录 |
| `PUBLIC_URL` | 对内开放时必填 | 用户访问工具的地址，默认 `http://localhost:4310`。用于生成 Lark 授权回调地址；以 `https://` 开头时 Cookie 只走 HTTPS |
| `LARK_BRAND` / `LARK_TARGET_BRAND` | 否 | 两边的平台，`lark` 或 `feishu`，默认 `lark` |
| `BIND_ADDRESS` | 否 | Docker 发布端口的地址，默认 `127.0.0.1` |
| `PORT` | 否 | 访问端口，默认 `4310` |
| `READ_CONCURRENCY` | 否 | 读取时同时处理的节点数，默认 `8`，上限 `32`，见[读取并发](#读取并发) |
| `WRITE_CONCURRENCY` | 否 | 迁移时同时写入的文档数，默认 `6`，上限 `16`，见[迁移并发](#迁移并发) |
| `HOST` | 否 | 不用 Docker 时的监听地址，默认 `127.0.0.1` |
| `DATA_DIR` | 否 | 数据目录，默认 `data`。Docker 下不生效 |

机器人只能访问自己所在组织的数据，所以跨组织迁移需要在两个组织各建一个机器人。

要让团队成员使用，还需要在**两个**机器人的开放平台后台配置：

1. 安全设置：把 `<PUBLIC_URL>/api/auth/lark/callback` 加到重定向 URL。
2. 权限管理：开通下面[机器人权限](#机器人权限)表中的权限（用户身份），以及 `offline_access`。
3. 发布新版本。

### 2. 启动

使用 Docker：

```bash
docker compose up -d --build
```

或者直接运行，需要 Node.js 22.13 及以上，无需安装依赖：

```bash
npm start
```

打开 http://127.0.0.1:4310 。

### 3. 迁移

以下是管理员的流程，成员按页面上的三步操作即可。

1. 输入源知识库链接，点击"开始读取"。
2. 读取完成后，在详情页确认文档数量和类型。
3. 输入目标知识库链接，点击"开始迁移"。
4. 查看进度：页面显示建目录和写内容两个阶段的进度、用时、预计剩余时间、各类型完成数，以及正在处理的文档和步骤（比如"上传图片和附件 3/12"）。"查看全部节点"可以看每个节点的状态和耗时。
5. 查看迁移结果。所有降级和失败都会列出来，失败的节点可以点击"重试未完成的节点"。

### 暂停、继续和重试

- **暂停**：读取和迁移都可以暂停。暂停后不再开始新的文档，正在处理的文档完成后才真正停下，所以会先显示"暂停中"。如果读取还在遍历目录，会等目录读取完才停。
- **继续**：从停下的地方接着做，已完成的文档不会重做。服务重启导致的中断也可以这样继续。
- **重试单个文档**：读取失败的文档会单独列出来，可以逐个重试，也可以一次重试全部。单个重试不影响正在进行的读取。
- 还有文档没读取完时不能开始迁移，避免未读取的文档被写成占位文档。
- 迁移已经生成的占位文档不会因为之后重试读取成功而更新，需要重新发起一次迁移。

## 补全图表

之前的版本不支持 Mermaid 图等扩展组件，迁移后这些位置是一行“[未迁移的内容: 扩展组件]”。管理员可以在“补全图表”页面把它们补回去，不用重新迁移：

1. 填入源文档链接（旧组织）和它迁移后的文档链接（新组织）。两个根节点直接对应，下面的子文档按标题一一对应，同名的按顺序对应。
2. 点“开始对比”。这一步只读不写，会列出每篇有图表的文档、图表数量和待补数量，以及在新位置找不到同名节点的源文档。
3. 确认后点“补上 N 张图”。每张图写回对应占位行的位置，然后删除占位行，文档其他内容不动。

只有当新文档里“已有的图表加上占位行”的数量和源文档的图表数量一致时，才会补这篇文档；否则标为“需手动处理”，不做改动，避免把图放错位置。补全过的文档再次对比会显示“无需补全”，重复执行不会多出图。

补全使用两边的机器人：源组织机器人读取，目标组织机器人写入，目标机器人需要对新文档有编辑权限。

## 机器人权限

| 内容 | 读取端 | 写入端 |
|---|---|---|
| 知识库 | `wiki:wiki:readonly` | `wiki:wiki` |
| 文档 | `docx:document:readonly` | `docx:document` |
| 云空间 | `drive:drive:readonly` | `drive:drive` |
| 电子表格 | `sheets:spreadsheet:readonly` | `sheets:spreadsheet` |
| 多维表格 | `bitable:app:readonly` | `bitable:app` |
| 导出 | `drive:export:readonly` | 不需要 |
| 画板 | `board:whiteboard:node:read` | `board:whiteboard:node:create` |
| 成员授权后保持登录 | `offline_access`（用户身份） | `offline_access`（用户身份） |

同一个机器人同时负责读写时，申请写入端这一列，再加上导出和画板读取两项。权限申请后需要发布新版本才会生效。

管理员按链接迁移时，机器人还需要能访问具体内容：源知识库至少可阅读，目标知识库可编辑。成员迁移用的是本人身份，不需要把机器人加到文档库。

## 读取并发

读取目录和内容时并发进行。每个接口组有独立的限速，低于实测上限；被限流时同组请求会一起暂停后重试。

| 接口组 | 实测上限（次/秒） | 工具限速（次/秒） |
|---|---|---|
| 文档块 | 6 | 5 |
| 画板 | 10 | 8 |
| 电子表格 | 约 10 | 8 |
| 多维表格 | 20 | 15 |
| 知识库 | 测到 20 未触发 | 15 |
| 其他（图片和附件下载等） | 测到约 5.6 个/秒未触发 | 8 |

`READ_CONCURRENCY` 默认是 8。每次调用通常要 0.6～1 秒，纯文字文档受文档块接口限制，大约 4～5 个并发就到顶了；8 为图片、附件留了余量。图片、附件多的目录可以调到 16，但提升有限，也会占用更多内存；遇到频繁限流或同时有别的程序在用这个机器人时，可以调低。

## 迁移并发

- **建目录**：不同父节点下可以同时创建。同一父节点下的子节点仍然逐个创建，因为新节点总是排在最后，同时创建会打乱顺序。
- **写内容**：多篇文档同时写入。同一篇文档内部仍然是串行，因为内容块是按位置写入的。

写入同样按接口组限速：

| 接口组 | 实测上限（次/秒） | 工具限速（次/秒） |
|---|---|---|
| 新建知识库节点 | 约 5，同一父节点下过快会锁冲突 | 4 |
| 文档写块 | 约 5 | 4 |
| 文档修改、删除块 | 约 3.5 | 3 |
| 图片和附件上传 | 测到 20 未触发 | 15 |
| 画板 | 测到 20 未触发 | 15 |
| 多维表格 | 测到约 14 未触发限流 | 10 |

`WRITE_CONCURRENCY` 默认是 6。这些接口每次调用通常要 0.7～1.4 秒，6 个并发基本能用满文档写块的限速。继续调大主要对图片、附件、画板多的目录有帮助。

几种情况提速有限：

- 所有文档都在同一个父节点下时，建目录仍然是逐个进行，每个节点约 1.4 秒。
- 一篇文档有很多图片时，每张图片都要修改一次内容块，整个工具最多约 3 张/秒。
- 一个很大的多维表格或电子表格只能由一个并发处理。

## 迁移范围

| 内容 | 处理方式 |
|---|---|
| 目录层级、标题、顺序 | 保留 |
| 文档正文、标题、列表、代码、引用、待办、高亮块、分栏、表格 | 保留 |
| 文档图片、附件 | 重新上传；无权下载的（如禁止下载的 MP4、PDF、PPT）会跳过，迁移后是文字占位，文档其余内容不受影响，跳过的文件和原因显示在结果中 |
| 文档之间的链接 | 指向迁移后的新文档 |
| 快捷方式 | 原文档在迁移范围内时保留，排在同级最后；否则生成说明文档 |
| 电子表格 | 通过 xlsx 导出再导入，单元格中的 @人员 变为文本 |
| 多维表格的数据表、字段、记录、附件、单向和双向关联 | 重建；无权下载的附件会跳过，记录保留 |
| 多维表格的视图 | 只保留名称和类型，筛选、排序、分组需要重设 |
| 多维表格的人员、公式、查找引用、自动编号字段 | 转为文本，保留当前值 |
| 多维表格的创建时间、修改时间字段 | 转为日期字段，保留原有时间 |
| Mermaid 图等扩展组件 | 原样重建，图的源码不变；目标组织不接受时转为文字，保留图的源码 |
| 画板 | 按节点重建，迁移后仍可编辑；便签作者无法保留，已隐藏；无权下载的图片替换为文字框 |
| 文档中 @ 的用户 | 转为文本，因为两个组织的用户 ID 不同 |
| 文档内嵌的电子表格 | 只迁移单元格的值，最多 100 行 100 列 |
| 文档内嵌的多维表格 | 重建被嵌入的那张表，字段和记录的规则同上；指向其他表的关联字段会跳过 |
| 群名片、任务、OKR 等 | 替换为文字占位 |
| 行内文件 | 跳过，并在迁移结果中提示 |
| 被 Lark 拒绝写入的内容块（如超过 1000 个块的大表格、嵌套过深） | 只有该块转为纯文本，其余内容正常迁移 |
| 思维笔记、幻灯片、旧版文档 | 生成占位文档并附原链接 |
| 知识库中单独的文件节点，下载或上传失败时 | 生成占位文档并附原链接，子节点不受影响 |
| 成员云空间的文件夹、文档、表格、多维表格、文件 | 在新账号云空间中按原层级重建，规则同上 |
| 成员云空间的快捷方式 | 原文件在迁移范围内时重建为快捷方式；否则生成说明文档 |
| 评论、版本历史、协作者权限、创建者和时间 | 不迁移 |

目前只支持知识库链接（`/wiki/<token>`），不支持云空间文件夹链接。

## 已知限制

- **成员流程尚未用真实账号实测**：授权、读写“我的文档库”目前只通过模拟接口测试过。Lark 文档没有写明 `my_library` 这个空间 ID 的用法。云空间的读取和重建用机器人自己的云空间实测过，用成员本人身份的读写还没有实测。
- **成员授权的有效期**：刷新令牌有效期由 Lark 决定（文档示例为 7 天），授权满 365 天后必须重新授权。失效后任务会报错，重新登录或授权后可以重试。
- **跨组织尚未实测**：目前的真实迁移都在同一个组织内的两个知识库之间完成，两个机器人的配置还没有实际跑过。
- **大体量尚未实测**：真实测试的规模是 7 个节点以内和一块 6000 多节点的画板，几千篇文档的耗时和限流情况还不清楚。
- **画板内的部分节点类型未验证**：表格、泳道图等节点还没有用真实数据测过。写入失败时该文档会标记为失败，不会悄悄丢内容。
- **重试可能产生重复节点**：创建知识库节点的接口没有幂等保护，服务器报错时工具不会自动重发，而是标记为失败。如果那次请求实际已成功，手动重试会多出一个节点。
- **工具没有删除功能**：重复迁移会产生多份内容，需要在 Lark 中手动删除。

## 数据和安全

- 所有数据接口都需要登录。管理员密码连续错 5 次，该地址锁定 15 分钟。
- **对内开放时请放在 HTTPS 反向代理后面**，并设置 `PUBLIC_URL` 和 `BIND_ADDRESS`。否则密码、登录 Cookie 和文档内容都以明文传输。经过反向代理时，密码锁定按代理的地址计算，错误次数过多会让所有人暂时无法用管理员登录。
- 不要暴露到公网：只有组织内成员能完成 Lark 授权的前提是机器人是企业自建应用；管理员入口只靠一个密码保护。
- 读取结果包含文档原文，保存在服务器上。Docker 下存放在 `lark-export-data` 卷中，直接运行时存放在 `data/`。有服务器和数据目录访问权限的人可以直接看到这些内容，页面上的隔离不覆盖这一层。
- 成员的 Lark 令牌用 App Secret 派生的密钥加密后存入数据库。更换 App Secret 后，成员需要重新授权。
- 成员和管理员都可以在页面上删除自己的读取记录，这会删除服务器上的文档内容、图片和附件。工具不会自动删除，迁移完成后建议删除。
- 删除 Docker 中的全部数据：

```bash
docker compose down -v
```
